# 制作记录 ·《复原力：一株会重新长成的植物》

艺术与科学课程小组作品 · 2026-11 · Pre 11/26
方法来源：Mordvintsev, Randazzo, Niklasson, Levin《Growing Neural Cellular Automata》(Distill, 2020)

> 本文档按课程要求**诚实记录全过程，包括失败**。所有数字来自本地训练日志与探针脚本，可复现（命令见文末）。

## 1. 选题转向：从《星空》到植物（失败记录）

第一阶段我们尝试让 NCA 记住并再生梵高《星空》的局部（512×288 多色油画）。v3–v11 共九轮迭代全部未达标：

- **初始状态不像星空**：色彩饱和度低、笔触糊成噪点；
- **再生失败**：擦除后长出的条纹方向与原图不对齐、月亮无法复原、出现杂色噪点；
- **persistent（永动）模式**退化为无结构乱码；
- 网页端还出现过 WebGL 管线频闪、擦除位置与鼠标不对齐等工程 bug（后已定位修复，但随旧 UI 一并归档）。

**结论（核心教训）**：瓶颈不是参数量（~1 万参数与官方一致），而是**任务复杂度**。官方示例的舒适区是 ~40–80px、平色、少色、轮廓清楚的图案；连续色调油画远超该方法的记忆与再生能力。继续加大参数/训练量属于无效军备竞赛。

失败证据完整归档于本地 `archive_starry/`（模型 v3/v11、训练日志、三模式录屏、对比图、旧 UI），可用于 Pre 的失败讨论环节。

经全组商讨，转向分工文档中的植物作品：**一株会重新长成的植物**——单种子生长＋擦除再生，目标图为小组原创程序化绘制（平色、≤5 色、80×80）。

## 2. 方法：官方配方忠实复现

先原样复现官方示例（分工文档要求），再训练植物。与官方 notebook 逐项对齐：

| 项 | 官方 recipe | 本实现 |
|---|---|---|
| 状态 | 16 通道 = RGBA（RGB 预乘 alpha）＋12 隐藏 | 相同 |
| 感知 | identity＋sobel_x/8＋sobel_y/8（3 核） | 相同（circular padding） |
| 更新网络 | 48→128(ReLU)→16，w2 零初始化**含 bias** | 相同，**8,336 参数** |
| 生命门控 | alpha>0.1 的 3×3 maxpool，pre＆post | 相同（死细胞恒为零） |
| 种子 | 单细胞 channels[3:]=1 | 相同（植物置于茎基部 40,64） |
| 训练池 | pool=1024，batch=8；每步最差样本换种子 | 相同 |
| 损伤课程 | batch 末 3 个样本随机圆盘擦除（r∈[0.1,0.4] 归一化） | 相同（官方 Regenerating 实验） |
| rollout | 每步 randint(64,96) | 初段相同；续训段 randint(96,160)（§3 几何修正） |
| 损失 | 逐样本 RGBA MSE | 相同 |
| 梯度 | 逐张量归一化 g/(‖g‖+1e-8) | 相同 |
| 优化 | Adam 2e-3，2000 步后 ×0.1，共 8000 步 | 相同 |
| 显示 | 1−alpha＋rgb（白底合成） | 相同 |

**与计划的一处调整**：原计划"先生长(G)后再生(R)"两阶段；实现改为直接从第 0 步使用官方**联合 Regenerating 配方**（pool＋种子槽＋圆盘损伤同时训练）。这正是官方"擦除后自然长回"示例的训练方式，生长能力由每步的种子槽保证，更简单也更忠实。

### M0 基线复现（管线验证，已通过）

目标：官方 planaria（48px，pad 16 → 80×66），2000 步，RTX 笔记本 ~8.8 it/s，约 4 分钟。

- 单种子 → 96 步长成完整个体：生长 MSE 0.0396（0 步）→ **0.0027**（96 步）；
- 接触表 `checkpoints/m0_emoji/growth_02000.png` 与官方 emoji 演示行为一致（早期边缘有彩色斑点，属官方同款早期现象）。

证明 seed/生命门控/padding/损失/pool 管线全部正确。

## 3. 植物训练（候选 A：粉花六叶，80×80）

- 目标图：`data/plant_A_80.png`（程序化原创，色板 5 色；候选 B 黄花 / C 极简芽 / A-64px 备用）；
- 命令：`python -m nca4plot.train_plant --target data/plant_A_80.png --iters 8000 --out checkpoints/plant_A`；
- 每 500 步存 checkpoint＋固定种子生长探针（8/16/32/48/64/96/128 步 MSE＋接触表）。

训练日志（growth_log.jsonl 摘录）：

| 1000 | 0.0076 | 0.0146 | 0.0103 |
| 2000 | 0.0052 | 0.0213 | 0.0112 |

| 4000 | 0.0029 | 0.0175 | 0.0050 |

### 8000 步中期验收与几何修正（诚实记录）

8000 步肉眼验收（`growth_08000.png`）：茎与六叶已干净、位置正确；**但花头仍为糊状粉色块，边缘青/品红噪点，黄色花心不清晰**——不达标，不进入验收。

原因分析：植株高 64px，单种子需 ~128 步长完；官方 randint(64,96) 窗口面向 ~40px emoji，对此几何使 loss 恒含"尚未长完"的不可消除误差分量（表现为 MSE@96 平台 ~0.015、MSE@128 持续下降）。

修正：自 8000 步续训至 16000（lr 自动 2e-4），**rollout 窗口平移为 randint(96,160)**，让梯度聚焦成熟态保真与噪点清理；其余仍为官方配方。续训 500 步即见效：MSE@96 0.0147→0.0088、MSE@128 0.0039→0.0024，128 步黄花心开始分离（`growth_08500.png`）。

（16000 步最终数字与肉眼验收见 §4。）

## 4. 验收：三种损伤测试（诚实记录）

探针：`python -m nca4plot.probe_plant --checkpoint checkpoints/plant_A/plant_latest.pt`
（固定 RNG；生长 128 步 → ①续跑 2048 步；②叶部小圆盘 r=6；③茎叶大圆盘 r=16；各 256 步恢复曲线＋接触表＋mp4。）

**离线探针（固定 RNG，`checkpoints/plant_A/probe/`，report.json）：**

- **生长**：单种子 → 128 步 MSE **0.0014**；接触表 `growth.png` 茎/六叶/粉瓣/黄心按目标位置长出。生长前沿带彩色火花（官方 emoji 同款现象），成熟后 dried。
- **测试①（不擦，续跑 2048 步）**：MSE 9.2e-05@256 → **7.3e-05@2048**，数值有限、形态稳定（`long.png` 四帧一致）——persistent 语义成立：不动它，它就一直保持。
- **测试②（小圆盘 r=6，叶部 45,50）**：擦后 0.0079 → 0.0018@32（**32 步达阈**）→ 7.7e-05@256。
- **测试③（大圆盘 r=16，茎叶 40,44）**：擦后 0.0191 → 0.0021@128 → **7.4e-04@256（256 步达阈）**。序列肉眼确认：茎尖萌芽→茎伸长→六叶位置复原→花头重建（`damage_big.png`）。

**网页 headless 验收（`scripts/verify_plant_web.py`，系统 Chrome＋WebGPU，`checkpoints/plant_web_verify/`）：**

- 后端 webgpu，8,336 参数；单种子自动生长 160 步恢复度 **96.5%**（前次运行 98.1%，随机更新掩码带来 ±2 个百分点方差，见 §6）；
- **真实鼠标**点击 grid(40,40)：擦除质心误差 **0.34 格**（<2 格门槛，星空阶段的偏移 bug 已消除）；
- 小块按钮：恢复度 76.9% → **99.3%**@256；大块按钮：21.7% → 76.2%@64 → **85.9%**@256（随机种子实例，见 §6 方差说明；离线固定种子同损伤达 98%+）；
- **频闪**：稳态相隔 700ms 两帧平均绝对差 **0.121/255**——无可见频闪（Canvas2D 管线＋稳态收敛）；
- **公网部署冒烟**（2026-11-22，headless Chrome＋WebGPU 直接访问 Pages）：生长 160 步 **97.8%**；大块损伤 30.2% → **82.0%**@256（随机实例，结构完整、颜色干净）；证据 `checkpoints/plant_public_smoke/`。
- 演示录屏：`media/plant_web/plant_demo.webm`（节流录制，生长→小损伤→再生→大损伤→再生→鼠标擦除→再生，全程可见）。

**结论：三种损伤测试全部通过，作品达标。** 残差与方差如实列于 §6。

## 5. 网页实现（极度精简）

- 单页 `web/index.html`＋`styles.css`＋`js/app.js`（合计 <400 行）：标题一行、480px 画布（80×80 最近邻 ×6）、目标小图、一行按钮、一行状态。
- 按钮：重新生长 / 暂停继续 / 笔刷± / 损伤测试小块·大块；快捷键 R / Space；拖动擦除。
- 渲染改为 **Canvas2D putImageData＋drawImage**（弃用 WebGL 厚涂管线）——从根上消除星空阶段的频闪类 bug；坐标映射按画布矩形换算，headless 实测擦除质心与点击位置误差 <2 格。
- 引擎 `web/js/nca.js`：ONNX Runtime Web（WebGPU→WASM 回退），每次推理 4 步；新增 `seed_mode:'single_cell'`（官方单种子启动）；植物 meta 关闭一切"回锚守卫"（guard:false）——**画面上每个像素都只来自 NCA 规则本身**。
- 演示节奏节流为 **40 步/秒**（每 100ms 跑 4 步）：单种子生长约 4 秒、再生过程肉眼完整可见，也便于 headless 录屏抽帧；单步推理仅 ~7ms，节流是为观察而非性能。
- 状态栏实时显示步数与"恢复度"（当前画面与目标图的 MSE 相对空白画布归一化），再生效果当场可量化。
- 本地：`python scripts/serve_web.py` → http://127.0.0.1:8765 。公网：https://wangcheng726.github.io/nca4plot/ （2026-11-22 经团队同意部署；push main 自动触发 `.github/workflows/pages.yml` 发布 `web/`）。

## 6. 已知局限（如实说明）

1. **边界 1 像素级彩色描边**：稳态轮廓上残留孤立彩色像素（学习到的不动点的一部分，2048 步内稳定不扩散，对 MSE 贡献 ~1e-4）。整体识别与再生不受影响；属方法在平色目标边界上的固有火花。
2. **再生保真存在采样方差**：离线固定种子大损伤恢复 98%+；网页随机更新掩码的个别实例约 82–93%（公网冒烟曾见 82.0%）（差异集中在叶缘 1 像素级形状，结构始终完整、颜色干净）。多次擦除/重试可得到更贴近目标的实例。
3. **生长阶段边缘彩色火花**：官方同款早期/前沿现象，成熟后收敛；不是 bug，是生长过程的可见痕迹。
4. **单一目标单一规则**：换目标图需重训（笔记本 GPU 一轮 ~30 分钟）；模型不"理解"植物，只记住这一株的形态发生场。
5. **80×80 网格、×6 最近邻显示**：像素风格是刻意选择（与官方示例一致），不是分辨率事故。
